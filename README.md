# 阿臭弟AI发送器

这是一个本地可视化工作流页面，用来把多阶段提示词和图片按顺序发送到指定 AI 聊天网页端。

## 运行

网页服务模式：

```powershell
cd E:\Prompt自动发送工作台
npm install
npm start
```

打开页面：

```text
http://localhost:8787
```

双击 `Prompt自动发送工作台.lnk` 时，会隐藏后台服务窗口，并优先使用 Edge App 模式打开工作台窗口；如果未检测到 Edge，则回退到普通浏览器打开。

如果需要排查启动问题，可以手动运行 `启动 Prompt自动发送工作台.bat`，该入口会保留可见命令行窗口用于查看错误。

桌面封装模式：

```text
E:\Prompt自动发送工作台\启动桌面版 Prompt自动发送工作台.bat
```

桌面版使用 Electron 独立窗口，原 Edge App 模式启动器仍然保留。

## 打包产物

已配置 Electron 打包命令：

```powershell
npm run dist
```

打包后产物位于：

```text
E:\Prompt自动发送工作台\dist
```

当前默认只生成：

```text
Prompt自动发送工作台-portable-1.0.0.exe   绿色版，双击即用
win-unpacked                              未压缩桌面程序目录
```

安装包先不默认生成。后续确实需要安装包时，再单独执行：

```powershell
npm run dist:installer
```

数据目录规则：

- 开发模式：数据保存在项目目录下的 `workflows`、`runs`、`tmp_uploads`。
- 绿色版：数据保存在绿色版 exe 同级目录下的 `app-data`。
- 安装版：后续单独生成安装包时，数据会保存在当前 Windows 用户数据目录下，不写入安装目录。

## 工作流保存

工作流会保存为本地 JSON 文件：

```text
E:\Prompt自动发送工作台\workflows
```

每个工作流一个文件。页面点击“保存”后，工作流下拉框会立刻多一个选项，后续可以随时读取。

工作流保存：

- 工作流名称
- 浏览器配置
- 当前阶段模块的自定义名称
- 当前阶段模块的提示词

工作流不保存：

- 图片
- 文件路径
- AI 平台回复
- 运行状态

## 页面状态自动恢复

页面会在浏览器本地自动记录当前工作现场，包括：

- 工作流名称
- 浏览器配置
- 当前阶段模块数量
- 每个阶段的自定义名称
- 每个阶段的提示词

重新打开页面时会自动恢复上次工作现场。图片和文件不会自动恢复，运行前需要重新选择。

## 当前能力

- 默认 1 个阶段模块，可在模块底部继续添加下一阶段。
- 从阶段 1 开始顺序执行。
- 遇到第一个既没有提示词也没有图片的阶段，工作流自动停止。
- 每个阶段固定执行“上传文件 / 填写提示词 / 发送”，不再提供“仅上传”模式。
- 上传区支持图片缩略图预览、继续追加文件、拖拽缩略图排序、单个文件删除。
- 上传区支持拖入文件夹；工作台会递归拆出图片文件，并按文件夹路径 + 文件名自然排序。
- 目标平台支持 ChatGPT、Gemini、豆包、DeepSeek 和自定义聊天页网址。
- 工作流下拉框第一项是“新建工作流”，选中后会进入空白新建状态；选中已有工作流会自动读取对应内容。
- “重载”按钮只用于手动重新读取当前选中的已有工作流。
- 每次点击“开始发送”，都会新开一个目标平台窗口执行。
- 顶部环境页签可以在同一个工作台里管理多个浏览器账号环境；点击 `+` 新建环境页签。
- 每个环境页签独立保存浏览器、目标平台、工作流、任务页、阶段内容、任务状态和进度。
- 顶部页签代表一个浏览器账号环境 + 一个目标 AI 网站。
- 同一页签内可以连续提交多条任务；任务会自动进入该页签队列。
- 当前页签内的任务切换统一通过右侧“任务列表”完成；任务列表底部可添加任务，单个任务右侧可删除。
- 每个任务页会独立保留阶段名称、提示词和本次运行期间选择的文件；文件仍然不会跨刷新或重启自动恢复。
- 同一浏览器环境下启动多个任务时，会自动进入队列；前一个任务结束后，下一个任务会在原浏览器环境中新开目标平台窗口继续执行。
- 多个 `http://localhost:8787` 页面也可以同时跑多套图。
- 每个任务绑定自己的目标平台窗口，避免互相抢输入框。
- 文件选择只在当前页面运行期间保留；刷新或重启工作台后需要重新选择图片 / 文件。

## 目标平台

- 默认发送到 ChatGPT。
- 可切换到 Gemini、豆包、DeepSeek。
- 可填写自定义聊天页网址。
- 工作流会保存目标平台配置。
- 多平台发送依赖网页端输入框、上传入口、发送按钮可以被识别；如果目标平台登录失效、弹窗遮挡、上传能力限制或网页结构变化，需要人工处理。

## 并行运行与同浏览器队列

- 顶部页签用于隔离浏览器账号环境和目标 AI 网站，不再把每个产品任务都拆成单独页签。
- 同一页签内可以连续点击“开始发送”，每次都会把当前编辑区内容提交为一条新任务。
- 同一页签内使用右侧“任务列表”切换任务页；任务列表会显示全部任务页，并在底部提供“添加任务”。
- 同一浏览器环境同一时间只实际执行一个任务。
- 如果在同一浏览器环境里启动多个任务，后台会自动排队，不会同时打开多个执行窗口抢输入框。
- 同浏览器队列中的前一个任务完成、失败或暂停后，下一个任务会在原浏览器环境中新开目标平台窗口继续执行。
- 当前页签右侧会显示该页签内的全部任务页、未提交任务、执行中任务、排队任务和阶段进度；排队显示蓝色，执行中显示绿色；执行中和排队中的任务不能删除。
- 一个任务正在 Edge 执行时，可以在另一个页面选择 Chrome / Brave / 其他自定义 Chromium 浏览器继续并行启动新产品任务。
- 也可以在同一个工作台窗口中用顶部环境页签分别配置 Edge、Chrome、Brave 或自定义 Chromium 浏览器后并行启动。
- 该规则用于控制本地任务隔离和输入框归属；不用于绕过任何平台限制。

## 浏览器

- 默认使用 Microsoft Edge。
- 可直接选择当前电脑已安装的 Chromium 内核浏览器：Edge、Chrome、Brave、Opera、Opera GX、Vivaldi、Chromium、QQ 浏览器、360 极速浏览器、360 安全浏览器。
- 如果列表中没有目标浏览器，选择“自定义 Chromium 浏览器路径”，粘贴对应浏览器的 `.exe` 文件路径。
- 该工作台依赖 Chromium 远程调试能力；Firefox、Safari、IE 不能按同一方式保证自动发送。
- 默认使用本工作台自己的独立资料目录，不读取原浏览器的 `Default` 用户资料；只有手动切换到“原浏览器资料”时，才需要填写原浏览器 Profile 名称。

## 执行边界

- 只负责自动上传、填提示词、发送、等待上一轮完成。
- 不下载 AI 平台输出。
- 不复检图片。
- 不重跑失败图。
- 不保存每轮对话内容。
- 登录失效、验证码、额度不足、网页改版、模型不支持上传时，需要人工处理。

## 独立浏览器资料目录

- 默认使用“独立资料目录（推荐）”，不会读取或修改你手动打开的原浏览器用户资料。
- 独立资料会保存在本地 `browser-profiles` 目录下，例如 `E:\Prompt自动发送工作台\browser-profiles\edge\Default`。
- 每个独立资料目录首次使用时需要单独登录目标平台；登录状态、主题、Cookie 和缓存只保存在该独立目录中。
- 同一个“浏览器 + 独立资料名称”的任务会自动排队执行；不同独立资料名称可以作为不同浏览器账号环境隔离运行。
- “原浏览器资料”只作为备用模式使用。该模式会尝试使用原浏览器 Profile 名称，例如 `Default` 或 `Profile 1`；如果原浏览器已经手动打开，可能无法接管，优先改用独立资料目录。
- 后台不会再全局关闭同名浏览器进程，避免影响你正常使用的浏览器窗口。
- 工作台页面会向后台发送窗口存活心跳；最后一个工作台窗口关闭后，后台会自动停止任务、断开自动化连接、关闭由工作台启动的浏览器进程，并退出本地服务。
